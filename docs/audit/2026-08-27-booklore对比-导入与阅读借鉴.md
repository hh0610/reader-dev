# booklore 对比调研：电子书导入与阅读翻页可借鉴之处

- 对比对象：<https://github.com/booklore-app/booklore>（自托管电子书/漫画库，Spring Boot + Angular）
- 默认分支是 `develop`（不是 `main`），Java 包名已由 `com.adityachandel.booklore` 改为 `org.booklore`——按旧路径抓会 404。
- 抓取方式：GitHub Trees API 取全量文件清单（2773 个文件），再逐个 raw 下载约 40 个关键源文件核对。
- **该仓库关闭了 Issues**（改用 Discussions，bug-reports 分类为空），所以本文第三节的"坑"全部是**读源码得出的实现缺陷，不是用户上报**。
- 本文所有代码引用均已比对过源文件原文，未经核对的推测已剔除。

我们的技术栈对照：Rust（lopdf + zip + quick-xml + scraper）+ Vue3 自研阅读器；booklore 是
PDFBox + epub4j + commons-compress + vendored foliate-js。**库不可直接复用，但解析策略、
容错顺序、传输架构、交互细节可以平移。**

## 一、导入解析

### 1.1 依赖选型（`booklore-api/build.gradle`）

| 用途 | booklore 用什么 | 对我们的意义 |
| --- | --- | --- |
| PDF | `pdfbox:3.0.8` + `jbig2-imageio` + `jai-imageio-jpeg2000` | **注意**：PDFBox 自身不解 JPEG2000/JBIG2，要外挂。我们用 lopdf 会撞上同样的墙——扫描版 PDF 内嵌 JPX/JBIG2 时目前解不开 |
| EPUB 元数据 | `epub4j-core:4.2.3` + `zip4j` | — |
| EPUB 阅读 | **不用 epub4j**，改用 `commons-compress` 手写 OPF/NCX/nav 解析 | 印证"元数据库好用但不够可控，阅读路径要自己解" |
| CBZ/CB7 | `commons-compress` + `xz` | — |
| CBR | `junrar:7.6.1`，**失败回退到 unrar CLI**（仓库自带 `docker/unrar/` 编译该二进制，因 junrar 不支持 RAR5） | "一个格式两条路径 + CLI 兜底"的思路可借鉴 |

### 1.2 EPUB TOC：nav 优先、NCX 兜底，且每步都有裸标签回退

`service/reader/EpubReaderService.java:296-322`：manifest 里同时找 `properties` 含 `nav` 的项与
`media-type=application/x-dtbncx+xml` 的项；先试 nav，抛异常则 `log.warn` 后转 NCX。

贯穿全文件的容错写法是**先按命名空间取，取不到再按裸标签名取**：

```java
NodeList items = opfDoc.getElementsByTagNameNS(OPF_NS, "item");
if (items.getLength() == 0) items = opfDoc.getElementsByTagName("item");
```

nav 内部还有二级兜底：先找 `epub:type="toc"` 的 `<nav>`，找不到就用第一个 `<nav>`（`:451-466`）。
`resolveHref` 手写 `/../` 归一化（`:676-692`）。

> **借鉴度：高。** 野生 EPUB 大量缺命名空间声明或用错前缀。我们在 `epub.rs` / `local_book.rs`
> 里已经统一按 `local_name()` 比对、忽略 prefix，等价于直接实现了它的回退路径——这条**我们已经做到位**，
> 可作为交叉验证。nav→NCX 的降级顺序我们也一致。

### 1.3 封面五级回退链

`service/metadata/extractor/EpubMetadataExtractor.java:91-209`，依次：

1. `epub4j.getCoverImage()`——单独 catch 了 `NullPointerException`，注释写明"通常是畸形 NCX 导致"
2. OPF 里 `properties="cover-image"` 或 EPUB2 的 `<meta name="cover" content="{id}">` → 查 manifest → 从 zip 取
3. manifest 启发式：`id` 或 `href` 含 "cover" **且** `media-type` 以 `image/` 开头
4. epub4j resources 全表扫描，同样的关键字 + 媒体类型判断
5. **兜底：裸扫 ZIP 条目名**，文件名含 "cover" 且后缀 jpg/jpeg/png/webp

CBX 侧（`CbxMetadataExtractor.java:621-637`）：先读 ComicInfo.xml 的 `<Page Type="FrontCover">`，
失败取按字母序第一张图。

> **借鉴度：高，成本极低。** 我们当前实现覆盖了 1–4 级（`properties`、EPUB2 间接 cover、
> `image_hrefs` 两遍扫描）。**缺第 5 级**——野生中文 EPUB 的 OPF 经常压根没声明封面，
> 加一段"扫 zip 找 `*cover*.{jpg,png,webp}`"是纯增量。

### 1.4 缩略图：统一 JPEG + 白底铺平 + 尺寸上限 + 随机 cache-buster

`util/FileService.java:699-773`：

- 落盘 `{dataDir}/images/{bookId}/cover.jpg` + `thumbnail.jpg`，**一律转 JPEG**
  （`TYPE_INT_RGB`，透明通道用 `g.drawImage(img, 0, 0, Color.WHITE, null)` 铺白底）
- 原图上限 **1000×1500**（注释明写 "prevent OOM"），超出等比缩
- 缩略图 **250×350**；源图宽高比在 0.85–1.15（有声书方形封面）时改 250×250
- `applyCoverCropping` 可配置智能裁黑白边
- **cache-buster 是 `BL-` + 13 位随机串，不是内容 hash**——纯粹为了换 URL 让浏览器重取

> **借鉴度：高。** 四点全部适用，Rust 用 `image` crate 几十行。随机串比算内容 hash 便宜得多，
> 且能配合 `Cache-Control: immutable`。我们现在封面走 data URI/直传，没有尺寸上限，
> 大封面 EPUB 有 OOM 风险。

### 1.5 稀疏采样 MD5 文件指纹（本次最值得抄的一段）

`service/file/FileFingerprint.java:14-43`，原文：

```java
final long base = 1024L;
for (int i = -1; i <= 10; i++) {
    long position = base << (2 * i);   // i=-1 时移位量为负，long 掩码到 62 位 → 溢出为 0（即文件头）
    if (position >= raf.length()) break;
    raf.seek(position);
    int read = raf.read(buffer);       // 每处只读 1KB
    if (read > 0) md5.update(buffer, 0, read);
}
```

**无论文件多大，最多只读 12KB**（12 次 seek × 1KB），偏移按 4 倍指数递增。

> 注：`i=-1` 那次是 `1024L << -2`，Java 对 long 的移位量取低 6 位（-2 → 62），
> `2^10 << 62` 溢出 long 归零，所以实际读的是**文件头**。看起来是无意为之但结果正好。
> Rust 里负移位根本不会编译，我们直接写死偏移数组 `[0, 1<<10, 1<<12, …]` 反而更清楚。

另有一套独立的库内查重（`service/book/DuplicateDetectionService.java`）：ISBN（isbn10 自动转 13）/
外部 ID（goodreads/hardcover/google/asin/comicvine，用**并查集**传递合并，`:89-129`）/
标题+作者 / 目录 / 文件名，五种策略可组合。

> **借鉴度：极高。** 直接对应用户已经提过的痛点——**同一个文件重复上传会生成 `(1) (2) (3)` 副本**。
> Rust 里就是 `File::seek` + `blake3` 循环约 30 行，导入前比指纹即可跳过。

### 1.6 目录监控：四组防抖常数 + 写入完成检测

`service/monitoring/LibraryWatchService.java`：Java NIO `WatchService`，`Files.walk` 递归注册每个子目录；
**处理 `OVERFLOW` 事件时降级为整库 rescan**（`:107-115`）；目录下放 `.ignore` 即跳过（`:496-505`）。

`service/watcher/LibraryFileEventProcessor.java:35-39`：

```java
DEBOUNCE_MS                 = 500L;     // DELETE 延迟 500ms 才处理
FOLDER_CREATE_DEBOUNCE_MS   = 5000L;    // 新建目录延迟 5s
PENDING_DELETION_GRACE_MS   = 8000L;    // 目录删除宽限 8s
STABILITY_CHECK_INTERVAL_MS = 3000L;    // mtime 稳定检查间隔
STABILITY_MAX_WAIT_MS       = 120000L;  // 最长等 2 分钟
```

三个精妙点：

1. **移动识别**：CREATE 事件会 cancel 掉同路径 pending 的 DELETE，从而把 "DELETE+CREATE"
   识别为"移动/修改"而非"删除后新增"（`:82-87`）
2. **批量拷贝合并**：目录内每新增一个文件就**重置该目录的 5s 定时器**（`:100-115`），整目录拷完才统一处理
3. **写入完成检测**（`checkStability`，`:515-543`）：轮询 mtime，直到"距上次修改 ≥3s"才认为写完，上限 120s

> **借鉴度：高。** 我们 `local_sync.rs` 的 watcher 目前没有稳定性检测——文件还在写入/下载时就可能被导入，
> 得到半截 EPUB。`notify` + tokio 定时器可完整复刻。`.ignore` 标记文件零成本。

### 1.7 元数据：字段级 locked + 完整度评分

来源枚举（`model/enums/MetadataProvider.java`）：Amazon、GoodReads、Google、Hardcover、
OpenLibrary、Comicvine、**Douban**、Lubimyczytac、Ranobedb、Audible。多数是 jsoup 抓 HTML。

`DoubanBookParser.java` 对中文场景最有参考价值：

- 搜索走 `search.douban.com/book/subject_search`，**从页面里的 `window.__DATA__ = {...};` 正则抠 JSON**
- 详情走 `book.douban.com/subject/{id}/`，CSS 选择器解析
- CJK 感知归一化正则 `[^a-zA-Z0-9一-鿿]`
- 中文日期全套：`(\d{4})年(\d{1,2})月(\d{1,2})日` / `年月` / `年`

两个设计单独点名：

- **字段级 locked**：`titleLocked` / `authorsLocked` / `coverLocked`… 每个元数据字段配一个布尔锁，
  自动刷新时跳过已锁字段
- **`metadataMatchScore`**（`service/metadata/MetadataMatchService.java:38-69`）：加权完整度评分，
  locked 视为已填，`(score/totalWeight)*100`，用于在列表里高亮"元数据不全"的条目

> **借鉴度：locked 机制极高。** 这正是"人工纠正过的字段，后续自动同步不要覆盖"的标准解法——
> 与你在别处提过的"追剧模式改了 tmdbid 之后不要被自动识别覆盖"是同一个模式。

## 二、阅读翻页

### 2.1 EPUB 阅读器：vendored **foliate-js**，不是 epub.js

`booklore-ui/package.json` 里**没有 epubjs 依赖**。引擎在 `booklore-ui/src/assets/foliate/`，
是 Foliate 桌面阅读器 Web 引擎的魔改内嵌副本：

```
view.js (21K)  paginator.js (44K)  epub.js (50K)  epubcfi.js (13K)
fixed-layout.js  mobi.js  fb2.js  comic-book.js  overlayer.js
search.js  tts.js  progress.js  text-walker.js
streaming-loader.js  ← booklore 自己加的
vendor/zip.js  vendor/fflate.js
```

Angular 侧只是薄封装：动态注入 `<script type="module" src="/assets/foliate/view.js">`，
再 `document.createElement('foliate-view')`。

### 2.2 分页机制：iframe + CSS 多栏 + scrollLeft 吸附

`assets/foliate/paginator.js`：

- 内容渲染在 `<iframe>`（`:213`）
- 分页模式 `columnize({width, height, gap, columnWidth})`：给 iframe 内文档设
  `column-width` + `column-gap`（`:309-317`）；滚动模式则 `column-width: auto` + 限宽
- 翻页 = 改 `scrollLeft`（竖排改 `scrollTop`，`:767-768`）
- 触摸：`touchstart`/`touchmove` 记速度，抬手 `snap(vx, vy)` 按方向吸附整页（`:804-815`）
- 单页/双页由 CSS 变量 `--_max-column-count` / `--_max-column-count-portrait` 控制，
  **竖屏自动降为单栏**（`:471-498`）
- **一个不知道就要 debug 一整天的坑**（`:659-661`，原文注释 "page-break-* unsupported in columns"）：

  ```js
  .replace(/page-break-(after|before|inside)\s*:/gi, (_, x) => `-webkit-column-break-${x}:`)
  ```

  多栏布局下 `page-break-*` 完全无效，必须替换成 `-webkit-column-break-*`，否则 EPUB 自带的
  分页控制全部失灵。

> **借鉴度：极高。** 这就是自研 EPUB 分页的标准答案。

### 2.3 EPUB 传输：服务端虚拟文件系统 + 客户端按需拉取

**这是架构上最值得学的一点，和我们现在"章节化 + 图片内联 data URI"是相反路线。**

服务端（`controller/EpubReaderController.java`）两个端点：

```
GET /api/v1/epub/{bookId}/info      → {containerPath, rootPath, spine[], manifest[], toc, metadata, coverPath}
GET /api/v1/epub/{bookId}/file/**   → 把 EPUB 内任意条目当静态文件流出（HTML/CSS/图片/字体）
```

`/file/**` 的安全与缓存（`:65-76`）：

```java
response.setHeader("Content-Security-Policy", "script-src 'none'");
response.setHeader("Cache-Control", "public, max-age=3600");
// 字体额外加 Access-Control-Allow-Origin: *
```

路径校验**双保险**（`EpubReaderService.java:710-715`）：既拒绝含 `..`，又要求命中**预计算的
manifest 白名单 Set**（O(1)）。元数据按"路径 + mtime"缓存在 `ConcurrentHashMap`，上限 50 条
按 `lastAccessed` 淘汰（`:229-260`）。

客户端（`assets/foliate/streaming-loader.js`）把 foliate 默认的"整包 zip 载入内存"loader 换成
HTTP loader，实现 `loadText` / `loadBlob` / `getSize`（从 manifest 查，不真读文件）/ **`getDirectUrl`**。

`getDirectUrl` 是给 foliate 打的关键补丁（`assets/foliate/epub.js:863-898, 970-991`）：

```js
// 图片不 fetch 成 blob，直接改写 src 指向服务端 URL，交给浏览器懒加载
el.setAttribute(attr, this.#getDirectUrl(path))
el.setAttribute('loading', 'lazy')
// CSS 里的 url()：字体和图片同样走 directUrl，不预取
```

外加自动给缺 `font-display` 的 `@font-face` 补 `font-display: swap`（`:1000-1004`）。

因为浏览器发起的 `<img src>` / CSS `url()` **带不了 Authorization 头**，`getDirectUrl` 把 JWT
放进 query string，服务端有专门的 `EpubStreamingJwtFilter` 同时接受 header 和 `?token=`。

> **借鉴度：极高，成本中等。** 我们现在把图片内联成 data URI，代价是：base64 膨胀 33%、
> 整章 HTML 体积暴涨、浏览器无法缓存单张图、无法懒加载、大图直接卡住渲染。
> 改成虚拟文件系统后，图片走原生懒加载 + 浏览器缓存 + 独立并发，收益是数量级的。

### 2.4 PDF：pdf.js + Range 请求

`features/readers/pdf-reader/pdf-reader.component.ts` 用 `ngx-extended-pdf-viewer`，两行是重点：

```ts
pdfDefaultOptions.rangeChunkSize = 512 * 1024;   // 512KB 分块
pdfDefaultOptions.disableAutoFetch = true;       // 禁止预取整本
```

对应服务端 `GET /api/v1/books/{bookId}/content` **明确支持 HTTP Range**
（`BookController.java:139-144` 的 OpenAPI 注解写了 206）。500MB 的 PDF 也只按需拉几百 KB。

服务端另有 PDF 转图片路径（`service/reader/PdfReaderService.java:234-251`）：
`renderImageWithDPI(page-1, 200f, ImageType.RGB)` 输出 JPEG（封面用 150 DPI）。
PDF 大纲用 `PDDocumentOutline` 递归，每项 `findDestinationPage` 反查页码（`:158-217`），
整段包在 try/catch 里，失败返回空目录。

> **借鉴度：Range 极高，渲染部分中。** 我们已有"扫描版 PDF 转图片书"，思路一致；
> **Range 是最容易漏又最划算的一项**。大纲"每项独立 try/catch，坏了跳过"的容错也值得抄——
> lopdf 解 outline 同样脆。

### 2.5 漫画阅读器：完全自研，设置项可当需求清单

`features/readers/cbx-reader/cbx-reader.component.ts`（48KB 单文件）。设置枚举
（`features/settings/user-management/user.service.ts:62-118`）：

```ts
CbxPageViewMode      = SINGLE_PAGE | TWO_PAGE
CbxScrollMode        = PAGINATED | INFINITE | LONG_STRIP     // 后两个即 webtoon 连续滚动
CbxReadingDirection  = LTR | RTL                             // 日漫右往左
CbxPageSpread        = EVEN | ODD                            // 双页错位对齐
CbxFitMode           = ACTUAL_SIZE | FIT_PAGE | FIT_WIDTH | FIT_HEIGHT | AUTO
CbxBackgroundColor   = GRAY | BLACK | WHITE
CbxSlideshowInterval = 3s | 5s | 10s | 15s | 30s
CbxMagnifierZoom     = 1.5x~4x    CbxMagnifierLensSize = 150~300px   // 放大镜
```

RTL 是**纯前端翻转**（`:929, 1077`），服务端页序不变。手机竖屏强制禁用双页（`:736`）。

三个交互细节决定体验好坏：

1. **预加载滑动窗口**（`:486-533`）：以当前页为中心前后各 2 步，`new Image()` 塞进
   `Map<string, HTMLImageElement>`；每次翻页 `cleanupPreloadedImages(keepPages)` 清掉窗口外的，
   避免长漫画吃爆内存
2. **翻页不闪白**（`:535-567`）：目标页全部 `img.complete && img.naturalWidth > 0` 才直接切 + 150ms 过渡；
   否则**保持旧页**并异步加载，全部 onload 后再切
3. **当前页判定**（`:761-820`）：无限滚动模式下遍历所有 `.page-image` 的 `getBoundingClientRect()`，
   找出**跨越容器垂直中线**的那张

> **借鉴度：高。** 这份枚举可直接当需求清单（尤其 RTL、LONG_STRIP、FIT_* 五种）。

### 2.6 进度与设置

| 格式 | 进度粒度 |
| --- | --- |
| EPUB | **EPUB CFI** + `href` + `fraction*100` 百分比，三者一起存（`state/progress.service.ts:87`） |
| PDF | 页码 + 百分比 |
| CBX | 页序号 + 百分比 |

三者额外跑一套 `ReadingSessionService`（start/update/end）用于统计。多设备同步靠服务端存储 +
**KOReader / Kobo 同步协议**（`service/koreader/`、`service/kobo/`、`service/opds/`）。

设置有**全局 vs 单本两级作用域**：
`perBookSetting.epub === 'Global' ? globalSettings : (individualSetting || globalSettings)`。

EPUB 设置全集（`state/reader-state.service.ts:9-56`）：`lineHeight`(0.8–3) / `justify` /
`hyphenate` / `maxColumnCount`(1–10) / `gap`(0–0.5) / `fontSize`(10–32) / `theme` /
`maxInlineSize`(400–1600) / `maxBlockSize`(600–2400) / `fontFamily`（含**用户上传字体**，
`custom:{id}` → blob URL 注入 `@font-face`）/ `isDark` / `flow: paginated|scrolled`。

主题注入的 CSS（`core/style.service.ts`）里几个细节值得单拎：

```css
html { hanging-punctuation: allow-end last; orphans: 2; widows: 2; }
h1..h6, hgroup, th { text-wrap: balance; }
pre { white-space: pre-wrap !important; tab-size: 2; }
aside[epub|type~="footnote"] { display: none; }
/* 浅色非白底主题下，让白底插图融进纸色 */
svg, img { background-color: transparent !important; mix-blend-mode: multiply; }
```

> **借鉴度：高。** `mix-blend-mode: multiply` 让白底插图在护眼/夜间主题下不再是刺眼白斑，
> 一行 CSS 收益很大。CFI + href + percent 三存也值得学：CFI 精确定位、href 快速跳章、
> percent 用于跨格式（同一本书 EPUB/PDF 两个版本）粗略同步。

## 三、性能与工程做法

### 3.1 大文件流式传输

- `/api/v1/books/{id}/content` **支持 Range / 206**，有独立的 `FileStreamingService`
- EPUB 从不整包读进内存：`/info` 只解析 OPF/NCX，`/file/**` 每次只流一个 zip 条目，64KB `BufferedInputStream`
- CBX 每次只解一张图

### 3.2 图片服务：不转码、不缩放

CBX 页面直接把 zip 里的原始字节流出去，**没有 WebP/AVIF 转换，没有按需缩放**。
缓存头由 `ImageCachingFilter.java` 统一加 `public, max-age=3600`。
只有封面/缩略图在导入时一次性转 JPEG 并落盘。

> **借鉴度：中。** "阅读页图片原样透传 + 只在导入时预生成封面缩略图"这个取舍是对的。
> 但 `max-age=3600` 偏保守——既然封面 URL 已带随机 cache-buster，可以直接上
> `immutable, max-age=31536000`。

### 3.3 读源码发现的实现缺陷（非用户上报）

1. **每次请求都重开压缩包**。`EpubReaderService.tryStreamEntryFromZip`（`:734-749`）和
   `CbxReaderService.streamEntryFromZipWithEncoding`（`:331-348`）每取一个条目就
   `ZipFile.builder().setPath(...).get()` 一次——一章 EPUB 有 30 张图就重解 30 次中央目录。
   7z/RAR 更糟：`streamEntryFrom7z`（`:364-375`）每次**线性遍历**到目标条目。
   它们缓存了"条目列表"，却没缓存"打开的句柄"。
   → **我们若做虚拟文件系统，务必缓存条目偏移量**（`zip` crate 可拿到 `data_start`）。
2. **CBX 页面 Content-Type 写死 `image/jpeg`**（`BookMediaController.java:74`），但支持的扩展名
   包含 `.png/.webp/.avif/.heic`。靠浏览器嗅探兜住了。→ 我们按扩展名映射真实 MIME，成本为零。
3. **ZIP 编码探测最多试 20 次**（`CbxReaderService.scanZipMetadata:226-258`）：5 种编码 × 4 种打开策略
   逐一 try-catch。结果会缓存，但首次很慢。
4. **两套并行的 ZIP/EPUB 技术栈**：阅读路径用 commons-compress，导入路径用 zip4j + epub4j——
   同一个 EPUB 在导入和阅读时走完全不同的解析，行为可能不一致。
   `EpubReaderService.java` 开头还有一段重复的 import 块（3-9 行和 18-23 行）。
5. **服务端 TOC 可能是白做的**：`/info` 返回了 `toc`，但前端读的是 `this.view.book.toc`，
   即 **foliate 客户端自己重新解析的 TOC**。两边各解一遍。
6. **自然排序有溢出风险**：`CbxReaderService.sortNaturally`（`:478-498`）对数字段用
   `Integer.parseInt`，遇到超长数字串会抛 `NumberFormatException`。
   → Rust 里比较数字段应"去前导零后先比长度再比字典序"，别解析成整数。

## 四、建议清单（按 收益/成本 排序）

### 1. ZIP 条目名编码回退链，链首加 GBK/GB18030 —— 收益极高 / 成本极低

参照 `CbxReaderService.ENCODINGS_TO_TRY`（UTF-8 → Shift_JIS → ISO-8859-1 → CP437 → MS932）。
**我们面向中文，必须在链首加 GBK/GB18030**（`encoding_rs`）。同时抄两点：把成功的编码
**缓存进 archive 元数据**下次直接用；条目过滤排除 `__MACOSX/`、`._*`、`.DS_Store`、
`Thumbs.db`、`desktop.ini`，且**按 `/` 分段检查 `..`**（不是简单 `contains("..")`）。

### 2. 稀疏采样指纹去重 —— 收益高 / 成本极低

偏移 `[0, 1<<10, 1<<12, …, 1<<30]`，每处读 1KB，最多 12KB，`blake3`。
导入时写进 books 表，扫描先比指纹，命中即跳过。
**直接解决已知问题：同一文件重复上传生成 `(1) (2) (3)` 副本。**

### 3. `/content` 与本地书资源端点支持 HTTP Range —— 收益高 / 成本极低

axum 用 `tower-http::services::ServeFile` 或 `axum-range` 即得 206。
前端 PDF 侧同步设 `rangeChunkSize = 512*1024` + `disableAutoFetch = true`。

### 4. 导入前做文件稳定性检查 + 事件防抖 —— 收益高 / 成本低

照抄那四组常数与逻辑：DELETE 延迟 500ms（CREATE 到来则取消 → 识别为移动）；
目录新建延迟 5s 且每有新文件就重置定时器；轮询 mtime 直到静默 ≥3s 才导入，上限 120s。
再加 `.ignore` 标记文件。**解决"文件还在写入/下载时就被导入成半截书"。**

### 5. EPUB 改为"服务端虚拟文件系统 + 前端按需拉取"，弃用 data URI 内联 —— 收益极高 / 成本中

新增 `GET /reader3/bookAsset/{id}/*path` 从 zip 流出条目；章节 HTML 只做 **URL 改写**
（`<img src>` 指向该端点 + `loading="lazy"`，CSS `url()` 同样改写），不再 base64 内联。

必须配套四件事：
(a) 路径校验用 **manifest 白名单 Set**，不能只查 `..`；
(b) 响应加 `Content-Security-Policy: script-src 'none'`；
(c) 加 `Cache-Control`；
(d) 浏览器子资源请求带不了 header，需支持 **`?token=` query 鉴权**（我们已有
`ASSET_TOKEN_COOKIE` 路径域 cookie 方案，可复用或并存）。

Rust 侧务必缓存 zip 中央目录/条目偏移，避免 booklore 那个"每次重开压缩包"的坑。

### 6. 封面第 5 级回退 + 缩略图归一化 + 随机 cache-buster —— 收益中高 / 成本低

补"裸扫 zip 找 `*cover*.jpg`"；统一转 JPEG、透明通道白底铺平、原图上限 1000×1500 防 OOM、
缩略图 250×350（方形源图 250×250）；封面 URL 挂随机串，换封面时换串，然后安全上 `immutable`。

### 7. Vue3 阅读器分页改用 iframe + CSS 多栏 + scrollLeft 吸附 —— 收益中高 / 成本中高

`column-width` + `column-gap` 分栏，翻页改 `scrollLeft`，触摸按速度 `snap` 到整页，
竖屏自动降单栏。**务必把内容里的 `page-break-*` 替换成 `-webkit-column-break-*`。**
顺带加 `svg,img { mix-blend-mode: multiply }`。

**替代方案（值得认真评估）**：像 booklore 一样直接 vendor foliate-js，只写薄封装层——
CFI、分页、搜索、TTS、注释全都白拿，成本可能远低于自研；代价是失去渲染细节的完全掌控，
且需要给它打 `getDirectUrl` 之类的补丁。

### 8. 元数据字段级 locked + 完整度评分 —— 收益中 / 成本中

每个元数据字段配 `*_locked` 布尔，自动刷新/重新匹配时跳过已锁字段；
再加加权 `match_score`（0–100，locked 视为已填），列表页高亮元数据不全的条目。
