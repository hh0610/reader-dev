实测收益：4.51MB 的轻小说，章节文本入库从约 6MB 降到 **83.7KB**。

**这一轮引入的行为变更（部署前需知悉）**：
1. **本地书正文里的图片从 data URI 变成 `/book-asset?...` 地址**。老数据不受影响
   （已入库的 data URI 照常显示）；新导入的书，**原文件必须留在原处**，删掉原文件
   会导致图片 404（文字仍可读）。上传导入的原文件本就落在 `data/{ns}/opds_files/`。
2. **secure 模式下 `getBookContent` 会下发 `Path=/book-asset` 的 HttpOnly cookie**，
   供浏览器 `<img>` 子请求鉴权。反向代理若剥离 Set-Cookie 需放行。
3. **books 表新增两列**（`file_hash`、`locked_fields`），幂等 `ensure_column` 自动补，
   旧库无需手工迁移。
4. **重复上传同一文件不再新建书**，直接返回原书；确需重导入用 `?force=1`。
5. **新增两个端点**：`/book-asset`（正文图片按需取）与 `/cover-thumb/{ns}/{file}`
   （封面缩略图）。反向代理若按路径白名单转发，需一并放行。
6. **书籍 JSON 新增四个只读字段**：`thumbUrl`、`metaScore`、`metaMissing`、
   `lockedFields`。老客户端忽略即可，不影响既有字段。

**测试**：`cargo test --lib` 811 全绿；前端 `node --test` 103 全绿；`vue-tsc` 无错。
3 个需真实 DNS 的 SSRF 测试在离线环境 2 秒超时自动跳过，有网时正常执行。
`test_get_system_info` 断言可用内存 ≠ "0M"，与编译并行跑时会偶发假失败，单跑通过。

## 行为变更（需要留意）

这几处**改变了对外可观察行为**，升级时请确认符合预期：

1. **目录/正文/详情解析为空 → 明确业务错误**（此前返回 `isSuccess:true` + 空数据）。
   前端若依赖「成功但空」来展示空态，需同步调整；好处是用户能看到真实错误而非空白。
2. **secure 模式下的收紧**（非 secure 单用户模式行为不变）：
   - MongoDB 备份/恢复需管理员/secureKey；
   - `/epub`、`/book-assets` 需 token 且 URL 首段命名空间必须匹配；
   - `getSystemInfo` / `getServerStats` 需登录。
3. **爬虫新增 `READER_HTTP_MAX_BYTES`**（缺省 32 MiB）：响应体超限报错。若有书源返回
   超大响应，需调大该值。
4. **多源搜索单源超时 25 秒**：极慢书源不再拖垮整批搜索，但其结果会缺失。
5. **正文分页上限 5 → 20**：超长分页章节不再被静默截断。
6. **PDF 正文排版重排**：lopdf 按绘制指令逐段输出（视觉一行被切成多段、标点单独成行），
   现拼回自然段并支持跨页续写。同一 PDF 导入后的章节内容与此前不同（更可读）。
   已知限制：文档首部的标题/作者/日期行会并入首段——缺少版面坐标信息无法可靠区分，
   正文主体不受影响。
7. **EPUB 章节标题**：spine 标题若与书名雷同视为占位符，由 toc 真实章名覆盖
   （Calibre 产物此前会出现"整本书每章都叫书名"）。
8. **secure 模式静态资源 cookie**：带 token 访问 `/epub` 章节 HTML 时下发
   `reader_asset_token`（HttpOnly + SameSite=Strict + Path 限定到该命名空间，1 小时），
   供页内相对 `<img>`/`<link>` 子请求鉴权；跨租户 cookie 同样被拒。

## 已知限制 / 未做

1. **`/assets` 静态目录仍未鉴权**：UI 上传的背景图经 CSS `url()` 加载，无法携带 token，
   强制鉴权会破坏功能。书籍正文（更敏感）已由 `/epub`、`/book-assets` 的命名空间校验覆盖。
   彻底方案需签名 URL，改动较大。
2. **源书正文缓存无 TTL / 不识别「坏数据」**：空正文已不再缓存；但非空的风控页/占位文本
   仍会被缓存。识别「坏」易误伤合法短章节，且加 TTL 需给 `book_chapters` 加列（schema 迁移），
   留待产品定义判据。
3. **PDF 封面仅支持内嵌 JPEG/JP2**：纯 lopdf 方案，零新增依赖，对扫描版 PDF 有效；
   矢量排版页无内嵌图则无封面。升级为整页渲染需引入 pdfium 原生库（见 EPUB/PDF 文档）。
4. **EPUB3 扩展元数据未接**：作者角色、系列、阅读方向、landmarks 等 komga 有的字段，
   reader-dev 的 `OpfMeta` 无对应字段，需先扩数据模型与前端展示。
5. **重定向仍有 SSRF rebinding 残余**：入口 host 已钉死校验过的 IP，但 reqwest 内部发起的
   重定向连接无法逐跳钉 IP（已在 `ssrf_redirect_policy` 注释说明），每跳仍做公网校验。
