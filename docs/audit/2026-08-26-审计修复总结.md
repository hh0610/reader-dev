# reader-dev 审计发现修复总结

对应审计报告 AUDIT-REPORT.md 的全量修复（本地分支 `fix/toc-empty-onclick-bookurl`，不推远端）。

多数越权类修复只在 **secure 多用户模式**改变行为；单用户模式保持原样。所有修复配单元测试或复用既有测试覆盖。

## Critical
- **C1 OPDS 任意文件读取**：`resolve_storage_file`(opds.rs) 补 canonicalize + storage 根容器校验；`saveBook` 增 `is_traversal_book_url` 拒绝 `storage//etc/passwd`、`storage/../..` 类注入（纵深防御）。
- **C2 MongoDB 备份/恢复越权**：`backup_to_mongodb`/`restore_from_mongodb` 改用 `check_manager_auth`（secureKey/admin 门槛），不再信任客户端 ns 当登录检查。

## High
- **H1 搜索 panic**：`build_search_url` 加 `start<end` 守卫；并给全局路由加 `CatchPanicLayer`（任一 handler panic → 500 JSON 而非断连）。
- **H2 静态服务鉴权**：`/epub`、`/book-assets` 经 `serve_data_file` 加 secure 模式命名空间校验（URL 首段=token 用户，admin 例外）。`/assets`（CSS 背景图，无法带 token）作已知限制保留——见「未完全修复」。
- **H3/H4/L8/L11 爬虫**：由爬虫实现代理修复（DNS 钉 IP 防 rebinding、响应体上限防解压炸弹、私网段补全、确定性错误不重试）。
- **H5 本地书章节 ns**：`save_local_book`/`save_chapters_ns`/`migrate_loc_book`/`replace_chapters` 四处 INSERT 绑定 `user_namespace`；`save_chapters` 保留 default 包装供测试。
- **H6 resolve_get panic / M1 XPath 静默空 / M12 / L6 / L12**：由解析引擎实现代理修复（畸形 @get 容错、HTML→XHTML 归一化重试、split 平衡切分等），166 parser 测试通过。
- **H7 静默失败簇**：getBookToc 空目录、getBookContent 空正文、getBookInfo 空书名 → 均改为明确业务错误，且失败不写缓存/不存进度。
- **H8 read_local_cover 穿越**：拒绝 `..` + canonicalize 容器校验。
- **H9 翻页去重/环检测 + init 后文档求值**：目录/正文翻页加 `visited` 集合防重复拼接与死循环；目录 nextTocUrl 改用 init 后文档求值。

## Medium
- **M2 setBookSource 空目录不缓存**；**M3 换源按旧章标题重定位进度**。
- **M4 percent_decode panic**（explore.rs + webdav.rs）：按字节解析 %XX，不切多字节字符。
- **M5 toc 缓存键**：新增 `get_toc_cache_by_book_url`，写入以真实 bookUrl 为键，4 处下游读取改用之。
- **M6 跨 ns 删除**：book_chapters/toc_cache 的 7 处 DELETE 改按自身 `user_namespace` 过滤。
- **M7 媒体回退泄漏**：规则存在但未命中 → 报错而非回退章节页 URL。
- **M8 探索 bookUrl**：`bookUrlPattern` 命中改用 `resp.url`（真实 URL）。
- **M9 探索 JSON 对象吞行**：括号配平扫描 + 单对象兜底解析，解析失败只跳当前行。
- **M10 {{}} 展开死循环**：加迭代上限 512。
- **M11 多源搜索单源超时**：每源 `tokio::time::timeout(25s)`。
- **M14 删用户遗漏表**：`delete_user_rows` 补 book_source_candidates/js_cache/book_vars_cache（并入 book_chapters/toc_cache 按 ns 直删）。
- **M15 迁移每次启动执行**：`migrate_admin_default_personal_data_back` 加 system_settings 一次性标记。
- **M9(路由) shelf_for_write 重复绑定**：删除 shadow 绑定，保留带 toc_url 兜底的首个。

## Low
- **L1 OPDS SHA-256 → argon2id**（新账号；旧 SHA-256 存储 verify 兼容）。
- **L2 token 常量时间比较**（主 token + token_map 成员判定）。
- **L3 getSystemInfo/getServerStats** secure 模式要求登录。
- **L4 resolve_secure_path** 补最深已存在祖先 canonicalize（防符号链接逃逸）。
- **L5 field_url 单斜杠 XPath** 不当字面路径（含 `/@`、`[@`、`/text()` 特征时走规则解析）。
- **L7 RSS vars 每条目独立**。
- **L9 token 读改写** 用 BEGIN IMMEDIATE 序列化。
- **L10 find_book_source LIKE** 转义 %/_/\ + ESCAPE。

## 真实订阅源端到端另修（XIU2/Yuedu 22 源测试发现）
- **正文 replaceRegex `##` 前缀污染**（book.rs analyze_content_from_with_vars）：源写
  `replaceRegex: "##[（(]本章未完.*[）)]|..."`（`##` 前缀=删除型正则），旧代码 splitn 得
  pat=空（空正则匹配每个字符间隙）、rep=正则文本，把规则文本逐字插进正文。剥离前导 `##`
  后按删除型处理。实测：阅友小说某章 75452 字乱码 → 修复后 2296 字干净正文。

## 端到端验证（真实源）
- 搜索→详情→目录（天帝传 809 章）→正文 全链路正常。
- H1：搜索 `>abc<` 不再 panic（日志 panic 计数 0，修复前 12）。
- H7：乱 tocUrl → `{"isSuccess":false,"errorMsg":"未解析到章节（书源目录规则可能失效）"}`。

## 交付与应用
- `reader-dev-fixes.bundle`（推荐）：`git fetch <bundle> fix/toc-empty-onclick-bookurl:fix-audit && git merge fix-audit`。
- `0001/0002 .patch`：本机 git（Apple Git 2.50.1）的 `git am` 对本组 patch 会误报冲突，
  但 diff 正确——改用 `git apply 0001*.patch && git apply 0002*.patch` 后自行 commit；
  其它 git 版本可直接 `git am`。详见「如何应用.txt」。

## 未完全修复 / 需产品决策（已在报告标注）
- **H2 `/assets` UI 上传（背景图）**：经 CSS `url()` 加载无法携带 token，强制鉴权会破坏功能。彻底修复需签名 URL 方案（较大改动），本次未动 `/assets`——书籍正文（更敏感）已由 `/epub`、`/book-assets` 的命名空间校验覆盖。
- **M13 源书正文缓存 TTL / 坏数据**：空正文已不再缓存（H7）；非空「坏数据」（风控页/占位文本）的识别易误伤合法短章节，且加 TTL 需给 book_chapters 加列（schema 迁移）——留待产品定义「坏」的判据后再做。
