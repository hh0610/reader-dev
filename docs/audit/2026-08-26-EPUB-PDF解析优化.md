# EPUB / PDF 解析优化（借鉴 komga-cn riir-dev）

依据 `2026-08-26-komga对比-EPUB-PDF借鉴.md` 的调研结论落地。komga 是图片型服务端
（PDF 只渲染成图、不做文本提取），因此本次只借鉴其 **EPUB XML 工程质量** 与 **封面** 思路；
reader-dev 原有的 PDF 文本提取 + 中文分章、解压炸弹上限、html5ever 容错 nav 解析均予保留。

改动文件：`src/service/epub.rs`、`src/service/local_book.rs`（不涉及网络/鉴权/存储）。

---

## 1. EPUB2 `<meta name="cover">` 间接封面（修「有封面识别不到」）

**问题**：`parse_opf` 的封面回退链只有 guide `reference type=cover`、manifest `id="cover"`、
`properties="cover-image"`，**缺少 EPUB2 最主流的间接方式**：
`<meta name="cover" content="封面item的id"/>` → 再用该 id 去 manifest 查 href。
Calibre 导出的 EPUB2 普遍用这种写法 → reader-dev 识别不到封面。

**改法**：解析时建立 manifest `id → href` 映射；封面按优先级回退：
`guide reference` → `properties=cover-image`（EPUB3）→ `meta name=cover`（EPUB2）→ `id=cover`。

**对应 komga**：`komga-rust/crates/epub/src/parse.rs:141 parse_epub_metadata_cover_id`。

## 2. OPF 元数据改用 quick-xml（修字段丢失）

**问题**：原为手写字符串提取，有三处硬伤：
- 标签写死 `<dc:` 前缀 → 默认命名空间（`<title>`）或其它前缀（`<opf:title>`）**整条字段丢失**；
- `decode_entities` 只覆盖 7 个命名实体 → **数字实体 `&#233;`/`&#xE9;` 不解**；
- 属性用 `key="val"` 子串匹配 → 属性顺序/单引号/多空格敏感。

**改法**：改用 `quick-xml`（**已在 Cargo.toml 依赖中，无新增依赖**）事件流解析：
- 标签按 **local-name** 匹配（`local_name()` 去前缀）→ 命名空间无关；
- 文本经 `unescape` + `Event::GeneralRef` 处理 → 数字实体与命名实体均正确还原
  （quick-xml 0.41 把实体作为独立事件发出，未知实体保留原文不丢字段）；
- 属性经 `attributes()` 解析读取 → 顺序/引号无关；
- 畸形 OPF 遇错即停但**保留已解析字段**，不 panic。

**对应 komga**：`media-metadata/src/refresh/epub.rs`（quick-xml 状态机 + `ends_with` 匹配）。

## 3. EPUB 资源路径归一化（修 `../` / `%20` 读不到）

**问题**：`resolve_opf_path` 只做 `目录 + '/' + href` 裸拼接。OPF/nav 位于子目录时，
`../images/cover.jpg` 拼出 `OEBPS/text/../images/cover.jpg` **匹配不到 zip 条目**；
`%20`、中文百分号编码路径同样读不到 → 封面丢失、章节读取失败。

**改法**：去 `#` 锚点 → percent-decode（按字节解析 `%XX`，避免多字节字符边界 panic）
→ 反斜杠转正斜杠 → 折叠 `.` / `..` 段（`normalize_zip_path`）；支持 `/` 开头的 zip 根绝对路径。

**对应 komga**：`parse.rs:286 normalize_epub_resource_href` + `:329 normalize_epub_zip_path`。

## 4. toc.ncx 改用 quick-xml（修 src 误取 / 层级拍平）

**问题**：`ncx_nav_points` 手写字符串扫描：
- `src` 用 `inner.find("content")` 后取**第一个引号值** → 属性乱序时取错
  （`<content id="c1" src="...">` 会读到 `c1`）；
- `</navPoint>` 按「最近闭合」匹配 → 嵌套 navPoint 时父点内容被截断；
- `stack` 变量声明后未使用（`let _ = &stack;`），层级信息丢失。

**改法**：quick-xml 事件流，命名空间无关（`<ncx:navPoint>` 同样命中）；
标题取 `navLabel/text`、链接取 **`content/@src` 属性名**；进入 navPoint 时占位、
闭合时回填 → 结果为**文档顺序（父先于子，深度优先）**，与 legado navMap 遍历一致。

**对应 komga**：`analysis.rs:758 ncx_link`（DOM 递归）。

## 5. PDF 封面（能力缺口，纯 lopdf 方案）

**问题**：`parse_pdf` 恒 `cover: None` —— PDF 导入无任何封面。

**改法**（`pdf_first_page_image`）：取首页 `Resources/XObject` 中第一个 `/Subtype /Image`：
- `DCTDecode`(JPEG) / `JPXDecode`(JP2)：**流数据本身即完整图片文件**，直接作封面；
- 其它滤镜（FlateDecode 位图等）需按色彩空间重编码，成本高易错 → 跳过；
- 宽或高 < 100px 的图跳过（避免把页眉 logo 当封面）。

**为何不用 pdfium**：komga 用 `pdfium-render` 渲染首页，效果最好，但引入**原生库
`libpdfium`**（打包/部署负担）。本次选纯 lopdf 兜底：**零新增依赖**，对扫描版 PDF
（首页整页即一张图）有效；矢量排版页无内嵌图则仍无封面。若将来接受原生依赖，
可按 komga 的 `artwork_support.rs:157 render_pdf_thumbnail` 升级为整页渲染。
