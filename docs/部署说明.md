# reader-dev 二进制部署说明

> 适用文件：交付包 `patches/bin/reader-dev-linux-x64.zip`
> （x86_64 Linux 静态链接 musl 二进制，**前端已内嵌**，零依赖——
> Debian/Ubuntu/CentOS/Alpine 拿来就跑，不需要装任何运行时）。
> 对应代码：`fix/toc-empty-onclick-bookurl` 分支 54 个提交。

---

## 一、快速开始

```bash
# 1. 解压并放到位
unzip reader-dev-linux-x64.zip
mkdir -p /opt/reader
mv reader-dev-linux-x64 /opt/reader/reader-dev
chmod +x /opt/reader/reader-dev

# 2. 建数据目录
mkdir -p /opt/reader/data

# 3. 启动
READER_APP_SECURE=true \
READER_APP_SECUREKEY='换成你的强密码' \
READER_APP_WORKDIR=/opt/reader/data \
READER_SERVER_PORT=8080 \
TZ=Asia/Shanghai \
/opt/reader/reader-dev
```

浏览器访问 `http://<host>:8080`，**注册的第一个用户自动成为管理员**。

- 只在内网单人用：可以不开 `READER_APP_SECURE`（免登录，数据都在 default 命名空间）。
- 公网或多人用：`SECURE` 必须开，`SECUREKEY` 必须是强密码（管理端操作要它）。

启动成功的标志：日志出现 `storage initialized` 和 `listening on 0.0.0.0:8080`。

> 唯一的功能限制：二进制不含 camoufox 浏览器后端（个别书源的验证码/滑块求解）。
> 绝大多数书源用不到；需要时在宿主机装 python3 + camoufox，
> 设 `READER_CAMOUFOX_SCRIPT=scripts/camoufox_solver.py` 即可接上。

## 二、systemd 常驻（推荐）

`/etc/systemd/system/reader-dev.service`：

```ini
[Unit]
Description=reader-dev
After=network.target

[Service]
User=reader
ExecStart=/opt/reader/reader-dev
Environment=READER_APP_SECURE=true
Environment=READER_APP_SECUREKEY=换成你的强密码
Environment=READER_APP_WORKDIR=/opt/reader/data
Environment=READER_SERVER_PORT=8080
Environment=TZ=Asia/Shanghai
Restart=on-failure
RestartSec=3

# 加固（静态二进制，只需要写数据目录）
ProtectSystem=strict
ReadWritePaths=/opt/reader/data
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
useradd -r -s /usr/sbin/nologin reader
chown -R reader:reader /opt/reader
systemctl daemon-reload
systemctl enable --now reader-dev
journalctl -u reader-dev -f        # 看日志
```

## 三、数据目录结构

`READER_APP_WORKDIR` 下会生成 `storage/`，**备份它就是备份一切**：

```
storage/
├── reader.db                 # SQLite 主库（书架/书源/章节/进度/用户，WAL 模式）
├── reader.db.bak-*           # 每次启动的自动快照，保留 5 份（READER_DB_BACKUP=0 关闭）
├── data/{用户名}/
│   ├── books/                # 本地书仓：把 epub/txt/pdf 丢进来即自动导入
│   ├── opds_files/           # 网页上传导入的原始文件 ⚠️ 不可手工删
│   └── webdav/legado/        # 每日自动备份 auto-YYYYMMDD.zip（保留 7 份）
├── assets/{用户名}/covers/    # 封面 + thumbs/ 缩略图
├── cache/images/             # 远程图片代理缓存（LRU 自动清理，默认上限 512MB）
├── js-cache/                 # 书源 JS 缓存
└── localStore/               # 书仓上传目录
```

⚠️ **`opds_files/` 与 `books/` 里的文件不可手工删除**：本版本起本地书的图片
按需从这些原始文件读取（不再整包塞进数据库），删了原文件该书图片会 404（文字仍可读）。
移除书籍请在界面操作——删书会自动连原件/封面/缩略图一起回收。

## 四、环境变量参考

只列常用的，全部变量可在源码 `grep READER_` 查证。**加粗**为公网部署必设。

### 核心

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| **READER_APP_SECURE** | false | 登录鉴权，多用户/公网必须开 |
| **READER_APP_SECUREKEY** | 空 | 管理密码 |
| READER_APP_WORKDIR | 当前目录 | 数据根目录 |
| READER_SERVER_PORT | 8080 | 监听端口（0.0.0.0） |
| READER_APP_INVITECODE | 空 | 注册邀请码（设置后注册需携带） |
| READER_TOKEN_TTL_DAYS | 30 | 登录有效期 |
| READER_APP_USERLIMIT | 100 | 最大用户数 |
| READER_APP_USERBOOKLIMIT | 50000 | 单用户书架上限 |
| READER_UPLOAD_MAX_MB | 100 | 上传上限；反代 body 上限要 ≥ 它 |

### 网络抓取

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| READER_HTTP_MAX_BYTES | 32MiB | 单响应体上限（书源返回超大响应时报错，可调大） |
| READER_HTTP_PROXY | 空 | 书源抓取出口代理 |
| READER_TRUSTED_PROXIES | 空 | 信任的反代 IP，正确解析 X-Forwarded-For 用 |

### 本地书 / 维护

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| READER_LOCAL_BOOK_DIR | 空 | 额外书仓目录（放文件自动导入，归 default 用户） |
| READER_LOCAL_SETTLE_MS | 3000 | 导入前「文件写完没有」的静默判定；慢盘/网盘挂载调大 |
| READER_BOOK_VARS_KEEP_DAYS | 30 | 书源 @put 变量缓存保留天数（≤0 关闭清理） |
| READER_AUTO_BACKUP_HOUR | 3 | 每日自动备份的整点（0–23） |
| READER_DB_BACKUP | 1 | 启动时 DB 快照开关 |
| READER_IMAGE_CACHE_MB | 512 | 图片代理磁盘缓存上限（0 禁用） |
| READER_LOG_DIR | 空 | 设置后日志落盘（配 _MAX_SIZE_MB / _MAX_FILES 轮转） |

## 五、反向代理（nginx 示例）

```nginx
server {
    listen 443 ssl;
    server_name reader.example.com;

    client_max_body_size 120m;          # ≥ READER_UPLOAD_MAX_MB

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # 配合后端 READER_TRUSTED_PROXIES=<反代IP> 才会信任此头
    }

    # SSE 流式接口：必须关缓冲，否则搜索/缓存进度不实时推送
    location ~ ^/reader3/(searchBookMultiSSE|searchBookSourceSSE|bookSourceDebugSSE|cacheBookSSE)$ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_buffering off;
        proxy_read_timeout 600s;
    }
}
```

三条硬性要求（括号里是违反的直接后果）：

1. **不要剥离 Set-Cookie**（登录鉴权模式下取正文时会下发 `Path=/book-asset` 的
   cookie 供图片子请求鉴权——剥掉则本地书图片全部 404）。
2. **按路径白名单转发的话，放行全部这些前缀**：
   `/reader3/`、`/assets/`、`/book-assets/`、`/epub/`、`/book-asset`、
   `/cover-thumb/`、`/opds`、`/simple/`、`/sw.js`、静态根 `/`。
   `/book-asset` 与 `/cover-thumb/` 是本版本新增，**老配置最容易漏这两个**。
3. **SSE 路径关 buffering** 并给足 `proxy_read_timeout`
   （多源搜索单源超时 25s，整轮可能数分钟）。

## 六、升级（换二进制）

```bash
# 1. 停服 + 备份（一个目录搞定）
systemctl stop reader-dev
cp -a /opt/reader/data/storage /opt/reader/storage-bak-$(date +%F)

# 2. 覆盖二进制
mv reader-dev-linux-x64 /opt/reader/reader-dev && chmod +x /opt/reader/reader-dev

# 3. 起服。数据库变更（新增列/索引/一次性回填）由启动时幂等迁移自动完成，无需手工 SQL。
systemctl start reader-dev
```

### 从旧版本升级到本版本，额外做一次存量清理

修复只管新数据，旧库大概率已积压两类垃圾（详见 `docs/audit/交付说明-给开发者.md` §4）：

```bash
# (a) book_vars_cache 膨胀——先自查：
sqlite3 storage/reader.db \
  "SELECT count(*), sum(length(vars_json))/1024/1024 AS mb FROM book_vars_cache;"
# mb 很大（实测案例：只读过几本书就 970MB）就清：
sqlite3 storage/reader.db "DELETE FROM book_vars_cache; VACUUM;"
# VACUUM 必须执行，否则 SQLite 不把空间还给操作系统、文件大小纹丝不动。
# 清空是安全的：丢的只是书源 @put 变量缓存，下次阅读会自动重建。

# (b) opds_files 孤儿（书早删了、上传原件还在）：
#     判定 = 文件名(去扩展名)在 books 表里没有对应 local://{文件名} 记录。
#     ⚠️ 别把书仓（books/ 目录）里的文件按此规则删——那是用户自己的原件。
```

### 升级后行为变化速查

- 解析失败明确报错（不再「成功但空白」）
- 重复上传同一文件返回原书，不再堆副本（确要重导入加 `?force=1`）
- 删书自动回收上传原件/封面/缩略图
- 新导入本地书的原文件不可再删（图片按需读取，见第三节 ⚠️）
- 首屏明显变快（主包 gzip 351KB → 59KB）——浏览器强缓存旧资源时 Ctrl+F5 一次

## 七、备份与恢复

三层备份各自独立：

| 层 | 时机 | 位置 | 保留 |
| --- | --- | --- | --- |
| DB 快照 | 每次启动 | `storage/reader.db.bak-*` | 5 份 |
| 全量 zip | 每日 03:00 | `data/{ns}/webdav/legado/auto-*.zip` | 7 份 |
| 手工 | 停服后打包 `storage/` | 自定 | — |

恢复 = 停服 → 还原 `storage/` → 起服。
注意 DB 是 WAL 模式：**不停服直接拷 `reader.db` 可能不一致**，
要么先停服，要么把 `reader.db-wal`、`reader.db-shm` 一并拷走。

## 八、排障速查

健康检查：`GET /` 返回 200 即就绪。

| 症状 | 先查什么 |
| --- | --- |
| 本地书图片 404、文字正常 | ① 原文件是否被删（`opds_files`/书仓）② 反代剥了 Set-Cookie ③ `/book-asset` 被路径白名单挡住 |
| 搜索进度不动、最后一次性全出 | 反代 SSE 路径没关 `proxy_buffering` |
| `reader.db` 异常大 | 升级清理 (a) 的 SQL；清后必须 VACUUM |
| 磁盘涨得快 | `reader.db.bak-*`×5 跟着 DB 一起大——先解决 DB；`cache/images` 会自动 LRU 不用管 |
| 上传大文件失败 | 反代 `client_max_body_size` < `READER_UPLOAD_MAX_MB` |
| 书源报「响应体超限」 | 调大 `READER_HTTP_MAX_BYTES` |
| 后台看到的客户端 IP 全是反代 IP | 设 `READER_TRUSTED_PROXIES` |
| 书仓丢文件进去迟迟不导入 | 文件还在写入（静默 3s 判定）；网盘挂载 mtime 怪异时调大 `READER_LOCAL_SETTLE_MS` |
| 个别书源要过验证码/滑块 | 二进制不含浏览器求解后端，见第一节末尾的接入方法 |
| 听书报「合成失败」且日志见 403 | 微软拒绝过旧的客户端版本号——对照 edge-tts 最新 constants 更新 `src/service/tts.rs` 里的 `CHROMIUM_FULL_VERSION` 重编（GEC 算法本身无需动） |
